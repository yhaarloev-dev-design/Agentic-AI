How I Work

From problem to working agent

The same process behind every project on this page.

01

Define the job

Get specific about the task, the inputs, and what "done well" looks like before writing a single prompt.

02

Design the prompt

Draft, test, and iterate the instructions, including guardrails, edge cases and failure modes.

03

04

Case Study

A deeper look at one project

A job search agent that reads every posting to the end

The problem. Job search results mislead. One role was listed as remote on the search card, but the last paragraph of the posting required three days a week in an office in another state. With dozens of new postings each weekday across three role tracks, the strong fits were getting buried.

What I built. A scheduled agent that runs 18 saved searches every weekday, reads each new posting in full and scores it with a written rubric. Every role gets a "why it fits" and a mandatory "watch-outs" note. The results feed a tracker with a dashboard, an application pipeline and one-click resume tailoring that can't invent experience.

What changed. On day one, 99 relevant roles were read and scored. Every weekday morning the new ones are waiting, with a one-line summary on my phone. Each feature (filters, pipeline, list view, tailoring, dashboard) came from using it and fixing what got in the way.
